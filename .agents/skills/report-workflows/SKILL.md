# Report Workflow 报表助手

## 定位任务

以本技能所在项目为工具箱根目录（本文件向上三级），不要依赖旧文档中的 Windows 绝对路径。先读 [业务路由](references/workflows.md)，只检查与当前任务有关的脚本。实际文件名和实现优先于 README 的旧名称。识别用户要处理的文件、当前流程阶段和期望结果；只追问影响执行的缺失信息。

按用户的业务目的选工具，不按序号连续执行所有脚本。两个 05、两个 14 必须用完整名称区分。用户说“拆分”时，结合录音/词曲、颜色、比例或街版语境确定具体操作；无法判断时先问一个明确的问题。

## 执行方式

- 优先复用现有脚本，保留字段、字体色、分组和公式语义。普通处理请求不意味着重构脚本。
- 数据仅在本机处理，遵守项目 `.cursor/rules/offline-local-files.mdc`。不上传报表，不为处理任务自行下载依赖。
- Mac 优先使用 `~/.venv/bin/python`；若不可用再检查项目 `.venv/bin/python`。检查所选脚本实际需要的本地依赖，缺失时说明缺什么，不自动安装。不在 Mac 启动 Windows COM。
- 多数入口是交互弹窗，并非命令行文件接口。运行前检查入口，不能凭空添加文件路径参数、`--dry-run` 或批处理参数。不要为了跳过弹窗而直接调用内部写入函数。
- 需要用户选文件时，明确告诉用户接下来选择哪个文件及哪些选项。可使用已有 `.command` 启动器或交互终端；启动 GUI 按环境要求申请执行权限。只观察已启动的进程，不反复重启。暂停在“按 Enter”或弹窗不等于处理失败。
- 用户已明确授权的报表操作直接推进，保留脚本已有确认。输入文件、比例、映射或忽略分组不明确时才询问，不猜业务选择。

## 写入与核验

执行前说明本次会写回哪个文件、导出什么结果；提醒关闭相关 Excel 文件。只使用用户指定的业务文件，不扫描整个桌面或读取无关报表。

先核实所选实现的备份与覆盖行为，不承诺统一的备份命名：部分脚本用 `.xlsx.bak`，共享模块可能使用日期备份；重复运行可能覆盖已有备份。如果现有备份会被覆盖且用户需要保留它，另存唯一名称副本后再运行。多文件同步（06）的影响范围包括同目录目标文件。

多数标准报表第 6 行为表头、第 7 行起为数据，但 10 的源表、14 版权比对表及 18 有不同设置。遵循对应脚本，不能全局套用默认行号。大表断点进度和 `.chunkwork.xlsx` 属于处理中状态，不删除、不当作完成结果；只有全部段完成并保存最终文件才报告完成。

核验应与任务相符：检查实际输出路径、相关页签、处理行数或金额，以及预期修改；保留公式和样式。`openpyxl` 不计算公式，缓存为空不能当作零，不能声称已重算。仅启动弹窗、退出码为零或生成文件都不足以证明用户选定任务完成。

结束时简短说明实际完成步骤、输出与备份路径、修改数量（若能可靠获得），以及仍需用户处理的事项。取消、等待人工选择或未完成的分段如实说明。
